# QR Data Transfer (Flutter app)

The native Flutter port of the QR Data Transfer PWA. It broadcasts a file as a continuous
stream of QR codes on your screen; the other device scans them with its camera, reassembles
the file with a RaptorQ fountain codec, verifies the SHA-256, and saves it. Fully offline:
no network, no pairing, no server. Wire-compatible with the PWA, so the two apps talk the
same protocol.

## Features

**Send** (Linux + Android)

- Per-transfer settings: display fps 12/15/24/30, bytes per tile 1/2/2.5 KB, tile layout
  1×1/1×3/3×1/2×2/3×3, high-refresh toggle
- Live speed + ETA estimate while you pick settings, live KB/s, k, fps and dropped stats
  on the broadcast stage
- Boost keeps the screen awake while you hold the device toward the other camera

**Receive** (Android)

- Live stats: decode fps, speed, ETA, dropped frames, progress bar, filename
- SHA-256 VERIFIED badge on completion (a mismatch is shown, never saved)
- Tap the saved-file card to open it with the default viewer

Brown Material 3 theme (seed `#6D4C41`, `DynamicSchemeVariant.content`), Fraunces display
type. Linux desktop is send-only (Receive shows a card pointing at the Android app); Android
does send + receive.

## Prerequisites

- **Flutter 3.44.8+ (stable)**. This environment uses Flutter 3.44.8 at
  `~/development/flutter/bin`:
  `export PATH="$HOME/development/flutter/bin:$PATH"`
- **Android SDK** (only for the APK)
- **GTK3 dev headers on Linux** (`libgtk-3-dev`)
- **Rust toolchain** (cargo), for the native codec
- **flutter_rust_bridge_codegen 2.12.0** (only needed if you regenerate the bridge):
  `cargo install flutter_rust_bridge_codegen --version 2.12.0 --locked`

Version-lock contract: the `flutter_rust_bridge` Dart package, the Rust crate and the codegen
CLI must all be exactly 2.12.0.

## Build & run

Commands assume you start from the repo root. Run them in this order.

### 1. Platform scaffolding (once, after a fresh clone)

The `android/` and `linux/` directories are gitignored and generated by `flutter create`, so
a fresh clone needs this step:

```bash
cd flutter_app
flutter create --platforms=android,linux --org com.qrtransfer --project-name qr_data_transfer .
```

### 2. Native codec (the Rust FFI library the app loads)

```bash
cd flutter_app/rust
cargo build
```

This produces `flutter_app/rust/target/debug/libqr_transfer_rust.so`. If the Rust API
changed, regenerate the bridge first:

```bash
flutter_rust_bridge_codegen generate \
  --rust-input crate::api \
  --rust-root flutter_app/rust \
  --dart-output flutter_app/core/lib/rust
```

### 3. Core tests (pure Dart, no Flutter needed)

The protocol, codec, sender and receiver logic live in `core/` and test with the standalone
Dart SDK, not Flutter's bundled one:

```bash
cd flutter_app/core
~/dart-sdk/bin/dart pub get
~/dart-sdk/bin/dart test
```

### 4. The app

```bash
cd flutter_app
flutter pub get
flutter run -d linux        # desktop
flutter build apk --debug   # Android; first build downloads the NDK (~1 GB, needs network)
```

## Usage

**Send** (Linux or Android):

1. Open the app, tap **Send**, choose a file.
2. Pick the per-transfer settings: display fps, bytes per tile, tile layout, high refresh.
   The panel shows the expected speed and ETA for your selection.
3. Tap **Begin broadcast** and hold the screen toward the other device's camera.
4. **Boost** keeps the screen awake. **Stop** returns to the settings step with the file
   still prepared, so going back does not re-chunk or re-encode. Only changing bytes per
   tile re-encodes (it changes the QR tile size). "Different file" clears the cache.

**Receive** (Android only):

1. Open the app on Android, tap **Receive**, allow the camera, tap **Start scanning**.
2. Point the camera at the sender's screen, steady, about 15 to 30 cm away.
3. Live stats (unique/k symbols, decode fps, speed, ETA, dropped) build up as frames decode.
4. When the file completes, the overlay shows **VERIFIED (SHA-256)**. Tap **Save file**,
   then tap the success card to open it with the default viewer.

Linux is send-only: the Receive tab shows a "Receive on your phone" card instead of the
camera view.

## Project structure

```
flutter_app/
  lib/            Flutter UI: entry (RustLib.init), brown M3 theme, adaptive shell
                  (NavigationBar < 600 / NavigationRail >= 600, Linux send-only),
                  send/settings/broadcast/receive views
  core/           pure-Dart package qr_transfer_core: protocol (wire/metadata/crc32c/
                  sha256), codec (RaptorQ FFI facade, deflate), sender (pacing/pipeline),
                  receiver (frames/stats/reassembler/decode_pool), QR encode,
                  FRB-generated bindings
  rust/           cargo crate qr_transfer_rust: raptorq 2.0.1 FFI API (flutter_rust_bridge
                  2.12.0) + interop tests
  test/           Flutter widget tests (theme, shell, send flow, receive flow, broadcast)
  assets/fonts/   Fraunces variable font, bundled for offline use
```

## Known notes

- Wire-compatible with the PWA: the interop tests prove the Flutter FFI decoder reassembles
  PWA-produced packets byte-identical, so both apps run on the same wire format.
- No encryption, deliberately: the threat model is a same-room visual broadcast. Anything
  the camera can see can be read.
- Each tile carries about 1.4/2/2.5 KB (V27/V34/V40 with ECC-L). Throughput is honest, not
  promised: on a 60 Hz display a 15 fps target quantizes to ~12 fps and the 24 fps cap to
  ~20 fps, and a 1 MB file takes roughly 20 to 60 s (measured ~46 KB/s for 1 MiB). Defaults
  are 2×2 grid, 1 KB tiles, 15 fps.
- The wire format caps a single transfer at 16 MiB (24-bit total length).
- The Settings tab is an info screen showing the defaults; the per-transfer settings live in
  the send flow.
